## Удалённый браузер для JavaScript-источников [выпущено и проверено]

3 октября 2026. Добавлен отдельный режим Chromium для HTML-источника. Владелец вручную открывает сайт в браузере VPS через снимки экрана, щелчки и ввод; сервер не передаёт ввод модели и не сохраняет значения в аудит. После явного сохранения Atlas шифрует браузерное состояние (cookies, localStorage и IndexedDB исходного origin) действующим `ATLAS_CONNECTOR_SESSION_KEY` на срок до 7 дней. Смена режима и новой сессии отзывает прежние разрешения и расписание. Scheduler применяет тот же проверенный CSS-рецепт к DOM после JavaScript и импортирует записи через прежний сервис. Запросы браузера ограничены origin источника; картинки/медиа и сторонние домены при автоматическом сборе блокируются. Произвольный код и DOM-запись по расписанию не выполняются.

Границы: входы через другой домен (в том числе многие OAuth), popup, CAPTCHA-картинки и сервисы с обязательным sessionStorage могут не сработать; запрошенный владельцем браузерный снимок может содержать личные данные, он отдаётся только аутентифицированному владельцу и не сохраняется. Для VPS работает отдельный Chromium-контейнер без доступа к БД и ключу шифрования; отдельные сеть управления и исходящая сеть задаются `compose.browser.yaml`. Вызовы из backend без настроенного сервиса закрыты; локальный запуск в процессе возможен только с явным `ATLAS_BROWSER_IN_PROCESS=1`. Прежний HTTP-режим остаётся режимом по умолчанию. Проверка живого стороннего аккаунта требует выбора сервиса и ручного входа владельца.

4 октября 2026: выпуск 0018→0023 установлен на VPS. Перед миграцией создана зашифрованная копия; миграция и данные 44 прежних таблиц проверены на восстановленной отдельной БД. После выпуска новая копия также успешно восстановлена отдельным штатным сервисом. Production: Alembic 0023, контейнер браузера запущен в отдельной сети, HTTPS health 200, закрытый API без входа 401; RPC браузера открыл публичную страницу, вернул снимок и закрыл сессию. Диагностическая сессия владельца после проверки API закрыта. Локально: 347 backend pytest, frontend build, 8 Vitest и 29 E2E; отдельная проверка JavaScript DOM в Chromium прошла. На живом залогиненном стороннем сайте вход, сбор и действия записи пока не проверялись: для этого владелец должен выбрать конкретный сервис и войти в него. Эти ограничения не позволяют обещать интеграцию с любым сайтом без адаптации.

Практическая проверка 4 октября: через интерфейс Atlas открыт Hleb Photos в браузере VPS, предпросмотр прочитал 11 текстовых карточек альбомов. Выявлено и исправлено падение предпросмотра после интерактивного открытия браузера; он использует общий Playwright runtime в одном потоке. Также исправлены подпись разрешения при выключенном источнике и чтение уже сохранённых записей владельцем. Сеанс закрыт без сохранения, расписание и доступ агента выключены, импорт не запускался, фотографии не скачивались и не сохранялись. Проверки после исправления: 348 backend pytest, frontend build, 8 Vitest и 29 E2E. Расширение Chrome через среду автоматизации не открывалось из-за ограничения доступа к служебным страницам браузера; его живой путь остаётся непроверенным в этой пробе.

## Сессии сайтов на VPS и проверяемые действия записи [выпущено 4 октября; ниже история разработки]

3 октября 2026. В расширение добавлена отдельная передача HTTPS cookies выбранного сохранённого источника после входа владельца в Chrome. Chrome запрашивает разрешение на cookies только для домена страницы; перед передачей владелец видит имена cookies и подтверждает действие. Atlas принимает их только для источника из `ATLAS_INTEGRATION_HOSTS`, шифрует Fernet-ключом `ATLAS_CONNECTOR_SESSION_KEY` из окружения VPS и хранит не дольше 7 дней. Значения не возвращаются через API, не включаются в модель, контентные записи или аудит. Серверный HTML/JSON сбор использует сессию для точного адреса источника без redirect; истёкшая сессия закрывает доступ, а не переводит сбор на публичный режим. Замена сессии отзывает прежнее расписание и действия записи.

В разделе интеграций добавлены действия записи: фиксированный POST/PUT/PATCH с JSON на том же разрешённом сайте и независимый GET для проверки точного поля. Опциональный CSRF-заголовок берётся из зашифрованного cookie по указанному имени. Для каждого запуска по умолчанию требуется отдельное разрешение. Регулярный PUT можно заранее разрешить на 7 дней и максимум 10 запусков после ввода названия действия; сервер хранит срок и лимит. Scheduler записывает намерение и начало в аудит до сетевого запроса, проверяет разрешение и версию сессии, после записи сверяет фактическое состояние. Таймаут, прерывание или несовпадение проверки дают `UNKNOWN`, отключают действие и исключают автоматический повтор. Отзыв авторазрешения отменяет ещё не начатые автоочереди.

Границы: вход выполняется в Chrome с явным переносом сессии; интерактивный браузер на VPS и сайты с обязательным JavaScript-рендерингом пока не поддерживаются. Нет исполнения скриптов модели, обхода MFA/CAPTCHA или записи через DOM. Реальный сторонний аккаунт и production не затрагивались. До выпуска нужны ключ шифрования в окружении каждого backend-процесса, backup/restore и миграция 0021→0022 на копии действующей БД.

Проверки: **342 backend pytest**, включая 0021→0022 на существующем источнике, зашифрованную сессию, cookie path, точные разрешения, CSRF, подтверждение, независимую проверку, отзыв, срок и отсутствие слепого повтора; **8 Vitest**, frontend build, Ruff по изменённым Python-файлам, синтаксис скриптов расширения и **28/28 изолированных E2E**. Первый общий E2E упал из-за остановки отдельного Vite после сбоя старого теста вложений; harness переведён на управляемый Playwright webServer, целый повтор прошёл. Старый тест инициатив дневника требовал реальную модель при `demo` окружении и был исправлен фиксированным тестовым решением; итоговая полная backend suite прошла. Живой сторонний сайт, перенесённая реальная сессия, production контейнеры и запуск на VPS не проверялись.

## Разрешения публичных интеграций и автоматизации [выпущено 4 октября; ниже история разработки]

3 октября 2026. Разрешение агенту читать записи источника и разрешение серверу собирать публичную страницу выдаются отдельно, на 30 дней по умолчанию (API допускает 1–90 дней). Оба привязаны к идентификатору, адресу и точному проверенному рецепту источника. Изменение рецепта или отключение источника отзывает оба разрешения. Каждый отдельный вызов чтения агентом по-прежнему требует подтверждения владельца. В интерфейсе показаны срок и состояние разрешений, есть отключение и повторная выдача. Внешние записи по расписанию не включались.

Scheduler проверяет разрешение перед сетевым запросом и перед импортом результата. Если разрешение истекло, сбор прекращается; результат запроса, полученный после отзыва, не импортируется. Миграция Alembic 0021 добавляет nullable поля, сохраняет прежние источники и записи, но отзывает старые разрешения чтения коннекторов. Старые расписания сохраняются в БД как историческая настройка, однако без новой привязки считаются недействительными и не выполняются; после наступления срока запуска scheduler очищает их. Новую выдачу должен сделать владелец после проверки источника.

Проверки: **326 backend pytest**, включая миграцию 0020→0021, отзыв при смене рецепта, истечение срока и отзыв во время запроса; **8 Vitest**, frontend build, Ruff по изменённым Python-файлам и **27/27 изолированных E2E**. Общий Ruff по всему backend пока сообщает о 26 ранее существовавших неиспользуемых импортах вне этого изменения. До production: резервная копия, проверка восстановления и миграции 0020→0021 на копии базы. Production не менялся.

## Большой кластер: потоковый «чат вслух» и локальное перебивание — 2 октября 2026

- Общий ModelRouter для chat принимает provider SSE: комментарии/heartbeat, многострочный `data`, текстовые delta, usage и обязательный `[DONE]`. Есть ограничения длины ответа, события и времени. HTTP-ошибка не вызывает повторный платный запрос; провайдер, возвращающий JSON вместо SSE, обрабатывается одним запросом как буферизованный ответ. Формат сверялся с [официальным описанием SSE OpenRouter](https://github.com/OpenRouterTeam/docs/blob/main/api_reference/streaming.mdx); это не заявление о подключении нового провайдера или проверке живого RouterAI.
- `SafeText` проверяет накопленный текст существующей политикой секретов, удерживает незавершённые слова и защитный хвост (минимум 80 символов либо длина самого длинного известного секрета). Текст выпускается смысловыми фрагментами, длинный абзац без пунктуации тоже продолжает поступать. Это не универсальная DLP и не необработанная выдача каждого токена. Входные секреты блокируются до запроса/резерва. Проверки покрывают разбиение известных секретов, bearer/sk-/password/api_key на каждой границе.
- `answer_fragments` — временный межпроцессный транспорт в общей БД; добавочная миграция `0014` не переписывает существующие задачи/разговоры. Публикация условным UPDATE проверяет действующий claim, RUNNING и срок аренды; отменённый/устаревший worker не может публиковать. Предыдущая попытка не переигрывается после восстановления. Работающий worker очищает фрагменты старше 24 часов и фрагменты неудачной генерации; канонический ответ остаётся Task/Message. Проверено обновление с существующей задачей через Alembic.
- mTLS gateway передаёт проверенные фрагменты до завершения, статусы, heartbeat и финальный ответ. На каждой итерации заново проверяет устройство/срок/голосовой разговор. При отзыве доступа закрывает уже открытый поток; при смене попытки отправляет reset без раскрытия claims. Ошибка после отправки HTTP-заголовков не превращается во второй HTTP-ответ. Планы, аргументы инструментов и credentials не передаются.
- `VoiceReply`/`ReplyController` вынесли сеть и TTS из цикла микрофона. Очередь ограничена 12 фрагментами, озвучка — 3500 символами; устройство воспроизведения сериализовано, число закрывающихся соединений ограничено. Отмена очищает очередь и соединение, блокирует устаревшие callbacks. Esc/PTT останавливают ожидание и озвучку; короткий Esc, замеченный самим Piper, отменяет всю очередь, а не одно предложение. Исходное удержание PTT при отправке не считается новым нажатием перебивания.
- При обрыве voice-клиент проверяет результат той же задачи: без новой отправки и повторного произнесения уже поставленного в очередь префикса. Отзыв доступа/reset не обходятся polling. Несовпадающий префикс, серверная ошибка или незавершённый частичный ответ прекращают озвучку. Финальный ответ старого gateway тоже проверяется локально на приватные данные до вывода/речи. CANCELLED отображается как отмена, не ожидание подтверждения.
- В настройки, профили, пример JSON и установщик добавлено opt-in `voice_interrupt_enabled` (по умолчанию false). Во время ответа отдельный Vosk использует только обращение + слова остановки и `[unk]`; остальные фразы, локальные действия и подтверждения не выполняются. Если модель не поддерживает ограниченную грамматику, остаются Esc/PTT. Пауза/выключение/диагностика прерывают ответ и останавливают захват. Серверные задачи и approvals не отменяются/разрешаются этим механизмом.
- Настоящий локальный прогон Piper через новую очередь: 2 фрагмента, 55808 отсчётов, 22050 Гц, 0,422 с синтеза двух фрагментов; звук не воспроизводился (sounddevice подменён). Заранее отменённый фрагмент не дошёл до воспроизведения. Это не задержка до звука на реальном устройстве.

Ограниченный контрольный словарь дал «атлас стоп» и сработал; «Атлас, сделай громче» и «Просто расскажи о погоде» остановку не вызвали. Микрофон не открывался, использована синтезированная речь; это не оценка речи владельца и не серия шумовых тестов.

Проверки: итоговый полный backend **224/224 PASS** (40 новых проверок относительно предыдущего кластера); **38/38 целевых stream/interrupt-тестов PASS**. Сквозные проверки используют настоящие локальные TCP HTTP/SSE и mTLS с тестовым provider-сервером: фрагмент приходит при RUNNING до финала, отзыв доступа прекращает поток. Тестовый provider не является LLM. **5/5 Vitest**, `npm run build`, Ruff, mypy — PASS; ESLint без ошибок, 7 прежних предупреждений `any`. Изолированный полный **11/11 E2E PASS без пропусков**; окно настроек проверено со штатным тестовым WebView bridge, скриншот осмотрен. Production БД и секреты в E2E не использовались.

Для включения: обновить серверные worker/gateway и применить `alembic upgrade head` (0014); полностью закрыть и заново запустить локальный Atlas Voice; при необходимости включить «Слушать „Атлас, стоп“ во время ответа». На старом сервере останется финальный ответ через совместимый путь. Акустического эхоподавления нет: наушники предпочтительны, колонки могут вызвать ложную остановку. Демо/agent не объявляются токеновым потоком LLM. Живой платный провайдер, микрофон владельца, музыка, p50/p95 и production-развёртывание остаются отдельной приёмкой.
