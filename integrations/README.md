# Как подключать новые сервисы к Atlas

Atlas поддерживает четыре пути подключения: готовый HTTP API, HTTP MCP с выбранными инструментами чтения, локальный браузерный адаптер для сайта с интерактивным входом и ограниченный серверный сбор публичного HTML/JSON. Для каждого сервиса нужны отдельные правила данных и действий: универсальный скрипт, который гарантированно работает с любым сайтом, невозможен из-за различий в API, HTML, авторизации и ограничениях сервисов.

Для сайта с капчей владелец проходит вход в обычном браузере. Адаптер использует уже открытую сессию и извлекает только нужные поля. По отдельному действию владельца расширение может передать cookies этого HTTPS-сайта на VPS: Atlas шифрует их ключом из `ATLAS_CONNECTOR_SESSION_KEY`, привязывает к источнику и хранит не дольше 7 дней. Пароли не передаются; значения cookies не попадают в модель, контентные записи, журнал и ответы API. На VPS используется только точный адрес источника и заранее разрешённый домен, без перенаправлений. Смена рецепта, отключение источника, отзыв или замена сессии останавливают расписание и действия записи. Пример расширения — `school-mos-chrome`. Оно не подменяет капчу и не пытается обходить блокировки.

Агент может предложить исходник нового адаптера и тестовые примеры, но код остаётся черновиком. Перед включением проверяются разрешённые домены, перечень полей, объём данных, права записи, журнал и тест на реальном сервисе. После этого владелец включает конкретный инструмент и отдельно подтверждает действия с последствиями. Atlas не предоставляет модели shell и не устанавливает/исполняет сгенерированные ею скрипты автоматически.

При выключенном ПК продолжают работать серверные REST/MCP интеграции, HTML/JSON источники с явно включённым расписанием, браузерный сбор JavaScript-страниц с сохранённым состоянием и уже сохранённые данные. Переданная из Chrome cookie-сессия работает для страниц, которые сервер получает как HTML или JSON; для JavaScript-страниц владелец включает отдельный режим браузера VPS. Локальный адаптер Chrome обновляет данные после следующего запуска компьютера и ручного действия владельца.

Для HTML-источника можно отдельно включить «Использовать браузер VPS». Владелец открывает страницу на VPS через снимок, вводит данные входа непосредственно в интерфейс управления браузером и явно сохраняет состояние на срок до 7 дней. Состояние браузера шифруется; ответы API не содержат cookies и localStorage. Плановый сбор затем ждёт элементы CSS-рецепта после JavaScript. Переходы и сетевые запросы ограничены сайтом источника; редиректы на отдельный домен входа и popup не поддерживаются. Расписание включается повторно после проверки результата. Это не универсальный обход защиты сайта и не право на автоматическую запись через DOM.

Действие записи задаётся без исполняемого скрипта: точные метод POST/PUT/PATCH, URL того же сайта, JSON-тело, отдельный GET-адрес проверки, поле и ожидаемое значение. Опционально CSRF-заголовок берётся из переданного cookie по имени и никогда не сохраняется в настройках действия. Каждый запуск требует отдельного разрешения владельца. Для регулярного точного PUT владелец может выдать ограниченное разрешение на срок и число запусков; оно привязано к рецепту и версии сессии. Перед записью создаётся запись запуска и аудит. После записи результат проверяется отдельным GET. Таймаут, ошибка проверки или прерывание дают статус `UNKNOWN`, останавливают действие и исключают автоматический повтор.

Серверный сбор включается отдельно после предпросмотра. Источник Hleb Photos использовался только для изолированной проверки механизма; его конфигурация не включена в поставку. Выпуск интеграций установлен на VPS 4 октября 2026 года с миграцией 0023 и проверкой восстановления зашифрованной копии. Реальный вход на сторонний сайт и выполнение действия записи в стороннем аккаунте пока не проверялись.

Для публичного источника есть два независимых разрешения: чтение сохранённых записей агентом и регулярный серверный сбор. Владелец выдаёт каждое на ограниченный срок (30 дней по умолчанию); разрешение закреплено за адресом и точным рецептом источника. Изменение рецепта или выключение источника отзывает оба. У каждого чтения агентом остаётся отдельное подтверждение. По истечении срока сбор прекращается, повторное включение требует проверки страницы с VPS. Уже сохранённые записи остаются доступными владельцу через интерфейс; отдельное право агента на них не продлевается автоматически. Серверный сбор умеет только читать публичные страницы и импортировать записи Atlas, без внешних записывающих действий.

Рецепт `public_json` читает верхний массив `collection`, вложенный массив `items` и только перечисленные `fields`. Поле вложенного объекта задаётся именем, поле родителя — `@parent.имя`. `image_url` преобразуется в абсолютный HTTPS адрес; отсутствие подписи даёт техническое название файла. Произвольный JSONPath, код, переходы по ссылкам и авторизация этим режимом не выполняются.
