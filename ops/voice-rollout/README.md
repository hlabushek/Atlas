# Развёртывание голоса — 2 октября 2026

Это сохранённая процедура для конкретного Atlas VPS, а не универсальный установщик. Production уже обновлена до 0014; `activate.sh` намеренно требует исходную 0011 и не предназначен для повторного запуска. Другие проекты и PostgreSQL/Redis не перезапускаются. Нельзя запускать при несовпадении `backend/requirements.lock` с установленным образом.

Release содержит только `backend/atlas`, `backend/migrations`, `backend/alembic.ini`, `backend/pyproject.toml`, `backend/requirements.lock`, проверенный `frontend/dist`, исходники `frontend/src`/`public`, package/lock/tsconfig/vite/index/nginx, `ops/desktop-gateway.compose.yaml`, оба backup shell-скрипта и этот каталог. `.env`, БД, сертификаты/ключи, node_modules и кэши в архив не входят. До prepare отдельно выполняются штатные backup/restore службы; release сверяется по SHA-256.

`prepare.sh` сохраняет исходники и образы, строит код на сохранённых образах без скачивания зависимостей, запускает pip check и `drill.sh`. Drill восстанавливает последнюю зашифрованную копию в отдельную временную PostgreSQL БД, проверяет Alembic и SHA-256 всех прежних данных; удаляется только эта восстановленная копия. После успешного drill `activate.sh` кратко останавливает Atlas, применяет добавочные миграции и пересоздаёт его процессы/интерфейс. Данные production не заменяются, автоматического downgrade нет.

Сохранённые образы имеют теги `atlas-<service>:pre-voice-20261002`, архив старых исходников — `/opt/atlas/staging/voice-20261002/pre-voice-source.tar.gz`. При проблеме сначала проверить причины и текущую ревизию БД; не удалять volume и не запускать downgrade/restore поверх production. Повторная смена образов требует отдельной проверенной процедуры.

После обновления `scripts/connect_voice.py` из Windows `.voice-venv` явно разрешает существующему mTLS устройству voice-доступ через owner API. Опциональный `--speak-test` отправляет один настоящий платный chat-запрос и делегирует настоящему аудиовыходу. Полный голосовой tray перезапускается отдельно. Результаты, ограничения и проверки записаны в PLAN.md.

## Настройки активации и моделей — отдельное UI-обновление

`settings-web.sh` — однократное обновление только web на этом же VPS. Не запускает migrate, не останавливает backend и не меняет модельные профили. До переключения сохраняет текущий web image с тегом `pre-settings-20261002` и исходники двух изменённых компонентов в `/opt/atlas/staging/voice-settings-20261002/pre-settings-web-source.tar.gz`; проверяет SHA-256 явно подготовленного архива. Тестируемый `frontend/dist` переносится в текущий nginx image без скачивания пакетов. На время пересоздания только web приостанавливается monitor timer, затем возвращается. В архиве только dist, два изменённых TSX, nginx.conf и эти deployment-файлы; env, БД и сертификатов нет. Выполняйте сохранённый LF-файл через bash на VPS: PowerShell pipeline может добавить завершающий CR в stdin.

Локальный Python-код голоса устанавливается из рабочей копии отдельно; для его применения перезапускается только Atlas Voice. Старое окно голосовых настроек следует закрыть и открыть заново. Настройки отвечающей LLM открываются по `/#models` и используют существующий owner login/API; голосовое mTLS-устройство не получает права менять модели.
