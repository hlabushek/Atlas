# Atlas — правила разработки
Документация и сообщения интерфейса на русском. Модульный монолит; интерфейсы используют единые сервисы.
Работать по PLAN.md. Каждый этап завершается тестами и честным отчётом. Не выдавать демо за LLM или заглушки за интеграции.
Секреты не попадают в Git, память, логи или запросы модели. Все API, кроме health и login, требуют аутентификации.
Никаких shell-инструментов для модели. Необратимые действия требуют разрешения, журнала и проверки фактического результата.
Перед изменением миграций учитывать существующие данные. В production только Alembic, никаких create_all при старте.
Проверки: backend — python -m pytest; frontend — npm run build и npm test; E2E — npm run test:e2e.
