# Чаты, настройки и мобильный интерфейс

## Управление разговорами

В библиотеке слева есть поиск по названию/описанию и фильтры «Все чаты», «Архив», «Корзина». В меню `⋯` — изменение названия/описания, закрепление, архив, корзина, восстановление. Закреплённые чаты идут первыми. История сообщений и результаты действий не редактируются: переименование меняет только метаданные. Корзина обратима, автоматического окончательного удаления нет. Архив/корзина доступны для чтения, отправка новых запросов закрыта до восстановления.

Активные задачи, действующие напоминания и привязанные voice/Telegram каналы защищены от архивирования/корзины с объяснением причины. Выполненные эффекты не откатываются. PATCH требует owner-auth, CSRF и актуальную `revision`; конфликт возвращает 409 без перезаписи другой сессии. Название/описание проверяются на секреты. Журнал изменений содержит ID/названия полей, не содержимое. Alembic 0017 добавляет метаданные с безопасными defaults, старые чаты остаются активными.

## Настройки

Одна кнопка «Настройки» открывает самостоятельный раздел: общие, модели, лимиты, данные, интеграции, Telegram, устройства, инструменты, навыки, дневник, инициативы и диагностика. Бюджеты, файлы, конфликтующие факты и эксплуатация не смешаны с подключениями. Загружаются только данные открытой категории. Разрешения остаются штатными, новые полномочия ИИ не добавлены.

Модели разделены на три роли. Несохранённый выбор сохраняется при переходе между категориями; сохранение по прежнему CAS-протоколу. Тарифы и технические пояснения раскрываются отдельно. Серверные ключи не возвращаются браузеру, реальные вызовы не делаются для декоративной проверки.

## Телефон

До 760 px приложение использует всю ширину экрана. Кнопка «Меню» открывает историю, личные разделы и настройки; фон недоступен для действий, фокус ограничен меню, Escape закрывает его и возвращает фокус. Выбор чата/раздела закрывает меню. Три главных режима доступны в верхней панели. Категории настроек — нативный список с группами; формы одноколоночные, поля 16 px, основные цели касания 44 px.

Редактор сообщения остаётся в рабочей области; длинная история прокручивается отдельно. Дополнительные голосовые действия и вложение свернуты по умолчанию. Закрытие их панели прекращает диктовку/озвучивание. Черновик не теряется при смене режима. Проверены браузерные viewport 320×568, 375×667, 390×844, 430×932; реальная клавиатура и микрофон телефона требуют отдельной живой проверки владельцем.

## Очистка демо

Владелец подтвердил: только доказанное демо, реальные/спорные данные сохранить. Доказательства: demo-профиль задачи, audit `reply_completed/provider=demo`, план исключительно встроенного демо-дневника, assignment `provider=demo`, память с явным demo/e2e происхождением. Совпадение по названию, содержимому или слову «демо» не является доказательством.

Настоящий provider usage, активные задачи, неизвестные результаты вызовов, любые эффекты вне демо-дневника, включая созданные заметки, защищают задачу. Demo-планировщик не превращает настоящий результат в одноразовые данные. Смешанный/пустой/неопределённый чат или чат проекта/канала сохраняется. Реальные школьные задания не удаляются. Действующий демо-дневник не разбирается под активной задачей.

`Данные → Очистка подтверждённого демо` показывает точные количества и digest плана; требуется фраза `СБРОСИТЬ ДЕМО`. Если план или сохраняемые данные изменились, транзакция отменяется. Перед commit проверяется отсутствие удалённых PK и SHA-256 всех сохраняемых строк (кроме живых heartbeat/session/voice-state); Audit, model/speech usage, owner memory, модели, устройства, бюджет и подключения сохраняются. Демо-grants закрываются только при удалении соответствующего встроенного навыка. Операция записывается в Audit. Это owner-maintenance API, не инструмент модели.

Кнопка интерфейса сама не создаёт backup. Серверный rollout сначала делает зашифрованную копию, восстанавливает отдельную PostgreSQL БД, проверяет аддитивную миграцию по прежним колонкам/хэшам и выполняет очистку на копии. Перед production-очисткой делается ещё одна копия с проверкой восстановления. Не выполнять downgrade или восстановление поверх живой БД автоматически.
