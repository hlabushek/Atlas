# Подключение моделей

Текущая двухмодельная схема владельца: [быстрый V4 Flash и вдумчивый V4.1 Flash](CHAT_ROUTING.md). Выбор отключается в настройках; голосовой стиль остаётся кратким. Это не меняет локальное распознавание Whisper.
Demo по умолчанию не требует ключей, не является LLM, показывает сохранённый запрос и найденный контекст.

Для Ollama установите и запустите Ollama, загрузите совместимую chat модель самостоятельно. Конфигурация:
```
ATLAS_MODEL_PROVIDER=ollama
ATLAS_MODEL_URL=http://host.docker.internal:11434/v1
ATLAS_MODEL_NAME=имя-установленной-модели
```
В запуске без Docker URL — http://127.0.0.1:11434/v1. Linux VPS без Docker Desktop требует host gateway или сетевой адрес Ollama; не публикуйте Ollama в интернет.

Для доверенного OpenAI-совместимого поставщика:
```
ATLAS_MODEL_PROVIDER=openai-compatible
ATLAS_MODEL_URL=https://ваш-провайдер/v1
ATLAS_MODEL_NAME=имя-модели
ATLAS_MODEL_API_KEY=ваш-секрет
```
После изменения окружения пересоздайте api/worker: `docker compose up -d --force-recreate api worker`.
Ключ передаётся только этому настроенному endpoint; redirects запрещены. Выбирайте URL самостоятельно, он не берётся из ответа модели. Поддерживается только текстовый chat completions, без native function calling/voice/embeddings. Для инструментальной задачи ModelRouter отдельно запрашивает JSON план из разрешённого каталога, затем проверяет его схемы; обычный chat completions не исполняет команды напрямую.

ATLAS_MAX_OUTPUT_TOKENS ограничивает размер ответа; контекст ограничен 12 сообщениями + 6 записями. Месячный UTC ledger резервирует токены до внешнего запроса и учитывает usage/неизвестный расход; тарифы задаются владельцем. Дневные/per-task лимиты и динамический выбор модели ещё не реализованы. Стоимость ledger выражена в микроUSD, поэтому рублёвые тарифы провайдера нельзя вводить как USD без явного пересчёта. Для первых тестов задайте также небольшой лимит ключа/баланса на стороне провайдера.

## Выбранные провайдеры — 29 сентября 2026
Владелец выбрал RouterAI основным, PlusVibeAPI — кандидатом для отдельного сравнения. Модели по умолчанию выбраны через постоянные настройки; live ключи ещё не заданы. Недоступная модель не подменяется demo.
По официальной документации оба поддерживают `/chat/completions` с Bearer авторизацией, что соответствует текущему адаптеру Atlas:

| Профиль | ATLAS_MODEL_PROVIDER | ATLAS_MODEL_URL |
|---|---|---|
| Основной RouterAI | openai-compatible | https://routerai.ru/api/v1 |
| Отдельный тест PlusVibeAPI | openai-compatible | https://plusvibeapi.ru/v1 |

Источники: [RouterAI](https://routerai.ru/docs/guides), [PlusVibeAPI](https://plusvibeapi.ru/docs). Идентификаторы моделей берите из каталога соответствующего провайдера: одинаковое отображаемое имя не гарантирует одинаковый API id. Объявленная совместимость не является проведённой live проверкой.
Atlas поддерживает сохранённые в БД роли main/planner/embedding и прежний environment профиль. Выбор меняется в Настройках; автоматический fallback между сервисами не включён. Тест второго поставщика должен использовать отдельную тестовую конфигурацию и синтетические запросы без истории/памяти владельца. Сравнение: доступность, задержки, русский текст, корректный JSON плана, usage, фактическое списание и повторяемость на одинаковых заданиях. Ответ модели «я такая-то модель» не доказывает её идентичность.
Нужны конкретные model ids, месячный бюджет и максимальная сумма теста; API keys добавляются только локально в игнорируемый secret файл, не в чат/документацию. Embeddings выбираются отдельно, текущий индекс требует 768 измерений; поддержка нужной модели/размерности этими поставщиками ещё не проверена.

## Настройки моделей в интерфейсе
Откройте **Настройки → Модели Atlas**. По умолчанию выбран RouterAI:
- Основной помощник: `deepseek/deepseek-v4.1-flash`.
- Сложные задачи и планирование: `anthropic/claude-sonnet-5.5`.
- Поиск по памяти: `qwen/qwen3-embedding-8b`, требуется ответ 768-dimensional.
- `google/gemini-3.8-flash` доступна как готовый вариант для любой текстовой роли.

Можно выбрать RouterAI/PlusVibeAPI или серверный провайдер (Ollama/другой совместимый API), загрузить каталог или вручную ввести model id. Идентификаторы не переводятся автоматически между поставщиками: берите ID из каталога выбранного сервиса. Сохранение не требует перезапуска. Конфликт изменения в двух вкладках возвращает 409; перечитайте настройки перед сохранением.
В чате переключатель «Режим ответа» выбирает основной профиль или сложную задачу. Автоматический planner агентных задач использует planner роль; явный план владельца по-прежнему не требует вызова LLM. Telegram использует main. В Task сохраняется не секретный snapshot модели/endpoint/лимита/тарифов; новые настройки не меняют уже созданную задачу. Ключ выбирается только по текущему серверному provider binding, в Task не копируется. Для старых задач без snapshot действует актуальный профиль.

Ключи сохраняются **только на сервере**:
- `ATLAS_ROUTERAI_API_KEY` в `.env` для Compose и `backend/.env` для локального SQLite профиля.
- `ATLAS_PLUSVIBE_API_KEY` — отдельный ключ PlusVibeAPI в тех же игнорируемых файлах.

В Settings API/БД/экспорте/аудите отсутствуют ключи; UI показывает только настроен ли ключ. Не вставляйте ключи в имя модели или чат — фильтр запрещает известные секреты. После изменения ключей пересоздайте api/worker/scheduler/telegram; выбор модели в UI применяется сразу. Старый `ATLAS_MODEL_API_KEY` может использоваться для RouterAI/PlusVibe только если старый ATLAS_MODEL_URL точно соответствует этому поставщику; ключ не пересылается другому сервису.
Без ключа выбранный профиль остаётся «не подключён», chat/plan завершаются понятной ошибкой до HTTP и расхода. Семантический поиск без готового провайдера выключен, keyword остаётся доступным. Live API доступность/качество/768 dimensions не подтверждаются одним наличием ключа; сначала выполните небольшой тест. Автоматического переключения на demo/другую модель нет.

При смене embedding provider/URL/model используется отдельный hash namespace. Старые векторы исключаются из retrieval; worker постепенно строит новый индекс. Исходная память не удаляется. Устаревший результат запроса не принимается, если профиль сменился во время HTTP. При смене весов под тем же ID namespace сам по себе не меняется — нужен новый model id или операторское обслуживание.
Тарифы можно задать **отдельно для каждой роли** в микроUSD за 1 млн токенов. Они фиксируются в snapshot задачи и используются до/после запроса. Нулевой тариф означает неизвестную стоимость, а не бесплатность. При включённом денежном лимите такой запрос блокируется. Рублёвые цены RouterAI/PlusVibe не вводите как USD без пересчёта. В Интеграции можно настроить месячные и дневные UTC token/cost лимиты и максимальную стоимость одной чат/agent задачи. Резервы перед HTTP учитываются; usage провайдера заменяет резерв после ответа, а неизвестный usage сохраняет резерв. Embeddings относятся к общим дневному/месячному лимитам, но не к стоимости отдельной задачи. Глобальные тарифы прежнего budget UI применяются только к environment профилю.

Миграция 0009 сохраняет существующие данные и оставляет прежний environment профиль при upgrade чужой установки. В текущих Compose/SQLite БД рекомендуемые профили включены отдельным действием владельца. Скрипт `scripts/configure_model_defaults.py` явно перезаписывает выбор рекомендуемыми значениями через owner API; не запускайте его, если хотите сохранить свои настройки.
Для E2E нужен серверный demo и выключенный переключатель «Использовать выбранные модели»: тесты не должны делать платные запросы. Новый E2E проверяет сохранение/перезагрузку/две вкладки и восстанавливает исходные настройки.
