# Интеграции этапа 6
## GitHub
`github.repo` читает метаданные публичного репозитория по owner/repo через фиксированный api.github.com. Это настоящий REST connector: без OAuth, private репозиториев, произвольных URL, redirect или записи. В Инструментах включите grant, затем создайте запрос в Интеграциях и подтвердите конкретный ToolCall. Результат сохраняется в общей задаче. HTTP 403/404/429 видны как ошибка задачи; безопасное чтение использует существующий ограниченный retry. Публичный octocat/Hello-World проверен реальным API.
Документация: [GitHub REST repositories](https://docs.github.com/en/rest/repos/repos).

## Embeddings и память
Настройте в игнорируемом `.env`: ATLAS_EMBEDDING_URL (совместимый `/v1` endpoint), ATLAS_EMBEDDING_MODEL, при необходимости ATLAS_EMBEDDING_API_KEY. Реальный `/embeddings` должен возвращать 768 конечных чисел, не нулевой вектор. Не подставляется demo embedding. Worker постепенно индексирует записи; ручная кнопка обрабатывает одну запись. Размер фиксирован (768), выбор провайдера/модели теперь меняется в Настройках. Отдельный namespace предотвращает смешивание моделей/endpoint; после смены worker строит новый индекс. Автоматическое определение изменения весов под тем же ID отсутствует.
PostgreSQL использует public.vector и cosine distance; SQLite хранит JSON векторы и считает cosine локально. Порядок семантического и словарного поиска объединяется reciprocal rank fusion. Редактирование и удаление инвалидируют вектор записи; удалённая/устаревшая/отключённая запись не извлекается. Embeddings — производные приватных данных: защищайте БД и backups как память. Нет ANN/HNSW индекса и автоматического определения естественно-языковых противоречий.
Одинаковый подтверждённый ключ факта с разными значениями создаёт конфликт. Владелец выбирает первое, второе или оба. Отклонённый факт исключается из retrieval, исходная запись остаётся видна для исправления. Редактирование сбрасывает подтверждённый факт и конфликт.
Адаптер проверен реальным локальным HTTP сервером с известными тестовыми векторами и PostgreSQL cosine. Это проверка протокола, не качество семантики live модели. Источник: [pgvector SQLAlchemy](https://github.com/pgvector/pgvector-python).

## Файлы и голос
Загрузка только UTF-8 txt/md/csv/json до 64 КиБ, максимум 5 вложений/100 КБ на запрос. Содержимое хранится в БД, не открывает произвольные пути и не исполняется. Выбранный файл явно добавляется в недоверенный контекст чата. Удаление вложения не удаляет уже сохранённые Message/Task. Фильтр известных секретов/шаблонов не заменяет проверку содержимого владельцем.
Web Speech API диктует текст в черновик по нажатию; отправка вручную. SpeechSynthesis читает последний ответ по нажатию. Поддержка определяется браузером; браузерное распознавание может обращаться к его облачному сервису. Реальный микрофон и русские голоса на машине не проверены. Telegram принимает ограниченные текстовые файлы и голосовые сообщения; голос передаётся RouterAI STT, расходы ведутся в отдельном RUB ledger. Server-side TTS нет; live STT и Telegram bot не проверялись. Источник: [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API).

## PWA и push
Manifest, standalone shell и service worker включаются в собранном приложении; dev Vite 5173 не регистрирует SW. Cache содержит только публичную оболочку/статические assets, никогда `/api` или сообщения. Офлайн оболочка не даёт доступа к приватной истории; после открытия нужен сервер.
Для push настройте ATLAS_VAPID_PRIVATE_KEY (base64url raw 32-byte EC private scalar), ATLAS_VAPID_PUBLIC_KEY (base64url uncompressed EC public point), ATLAS_VAPID_SUBJECT (`mailto:...`). Храните private только в `.env`; не вставляйте в UI/чат/память. HTTPS и разрешение браузера обязательны, кроме browser localhost exceptions. Subscription не экспортируется и не передаётся модели. Endpoint ограничен ATLAS_PUSH_HOSTS: по умолчанию FCM/Mozilla/Apple. Только разрешённые HTTPS endpoints, валидные EC keys, без redirects.
Включите инициативы, затем push для текущего браузера. Сообщение содержит только «Новая инициатива. Откройте Atlas», без содержания инициативы. Durable intent/dedup, quiet hours/opt-out/expiry/answer перепроверяются перед send. Таймаут после intent остаётся UNKNOWN без автоматического повтора; отписка 404/410 отключает subscription. Один push на инициативу, без повторных push reminders. Реальная pywebpush криптография проверена шифрованием/расшифрованием тестового получателя; transport в этом тесте заменён, live push устройство не подключено. Источник: [Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API).

## Бюджет
Каждый внешний запрос chat/plan/embedding резервирует токены до HTTP; конкурирующие процессы сериализуют ledger через блокировку Budget. После ответа usage уточняет расход. Отсутствие usage, HTTP ошибка и crash оставляют UNKNOWN/RESERVED с удержанным лимитом. Demo не расходует внешний бюджет. Резерв input — консервативное число UTF-8 байт JSON, не результат tokenizer.
Месячный UTC лимит токенов; необязательный месячный лимит стоимости. Цены задаёт владелец в микроUSD за миллион входных/выходных токенов. Без тарифов стоимость неизвестна, не выдумывается. При включении ограничения стоимости старые записи без известной стоимости блокируют дальнейшие платные запросы до следующего месяца/операторского reconciliation. Неизвестные тарифы не считаются нулём. Usage больше резерва записывается фактически, следующие запросы блокируются. Дневные лимиты, совокупный бюджет одной agent task и автоматический выбор дешёвой/сложной модели остаются открытыми требованиями исходного ТЗ.
