# Desktop Companion — этап 5
## Профиль владельца: Windows ↔ production VPS (30 сентября 2026)
Windows Companion установлен в профиле владельца и запускается при входе через пользовательский ключ Run. Он обращается только исходящим HTTPS/mTLS к `https://atlas.prism-news.xyz:9443`; локальный корень ограничен проектом Atlas. Сертификат устройства зарегистрирован в production, права сервера — `read_text`, `list`, `create_text` и `launch_file`; общие `desktop.read` и `desktop.write` включены, каждое действие требует отдельного подтверждения. Локальный запрос к gateway прошёл проверку TLS и авторизации, вернулся штатный ответ без ожидающей команды. Процесс Companion подтверждён запущенным.

Для отзыва отключите устройство в Atlas → Устройства; для остановки Windows процесса завершите локальный процесс Companion и удалите `AtlasCompanion` из пользовательского ключа автозапуска Windows Run. Gateway слушает 9443; 8443 на VPS используется другим проектом.

Дополнение: локальный профиль владельца разрешает `create_text` и `launch_file`, серверное устройство и глобальный `desktop.write` также включены. Каждый вызов требует отдельного подтверждения. `launch_file` принимает только документ внутри разрешённого корня и псевдоним приложения из локального `companion.json`; сейчас указан `notepad` для TXT/MD/CSV/JSON. Исполняемые файлы, скрипты, ярлыки и оболочки запрещены. Автозапуск перенесён в пользовательский Windows Run: Планировщик не удерживал процесс в этой сессии; его старая задача отключена. Проверка mTLS и живого процесса прошла.

## Что работает
Companion — Python процесс с исходящими HTTPS запросами, без входящего порта. Gateway отдельный процесс монолита, использует общую БД и сервисы. TLS требует клиентский сертификат, CA проверяет цепочку/срок/назначение, fingerprint SHA-256 берётся из SSLSocket.getpeercert(binary_form=True), не из заголовка. Клиент проверяет server certificate и hostname; redirects/proxy из среды отключены.
Владелец регистрирует public fingerprint в Устройствах. Регистрация не включает доступ: отдельно enabled, root aliases, operations, expires_at. Локальный JSON независимо задаёт enabled/expiry, mapping alias→directory и allowlist operations. Каждый desktop.read требует глобального tool grant и отдельного scoped approval. Сервер перепроверяет доступ при enqueue/poll/permit/result; Companion перечитывает локальную конфигурацию непосредственно перед чтением. В UI доступны история, последнее подключение, отзыв и запуск запроса.
Операции фиксированы: read_text (UTF-8 regular file до 64 КиБ), list (до 100 записей) и create_text (новый UTF-8 TXT/MD/CSV/JSON до 64 КиБ). Модель передаёт alias и relative path, не абсолютный путь. Создание идёт во временный файл с атомарным no-overwrite добавлением: существующая цель никогда не заменяется. Родительские каталоги должны быть созданы заранее; целевые расширения ограничены, секретоподобное содержимое отклоняется. `desktop.write` имеет отдельный глобальный grant, отдельные локальный и серверный operation grants и scoped approval на точное содержимое/path.
Нет перезаписи/редактирования существующих файлов, удаления, команд оболочки или browser automation. Открытие документа выполняется только выбранной в локальном профиле программой без произвольных аргументов, после отдельного подтверждения.

## Локальный запуск
Из корня проекта, в окружении .venv со стандартными backend зависимостями:
```powershell
.\.venv\Scripts\python.exe scripts\create_desktop_certificates.py .sessions\desktop
```
Это создаёт dev CA/server/device certificates на 30 дней и показывает только public fingerprint. Файлы уже существующих ключей не перезаписываются. Не устанавливает доверие в Windows. Для постоянной эксплуатации используйте свою PKI и ротацию; права Windows на каталог/key ограничьте владельцем, CA key не передавайте устройству.

Gateway должен использовать те же переменные DB/owner config, что API/worker. Для проверки локального SQLite профиля из backend:
```powershell
$env:ATLAS_DESKTOP_CERT = (Resolve-Path ../.sessions/desktop/server.pem).Path
$env:ATLAS_DESKTOP_KEY = (Resolve-Path ../.sessions/desktop/server.key).Path
$env:ATLAS_DESKTOP_CA = (Resolve-Path ../.sessions/desktop/ca.pem).Path
..\.venv\Scripts\python.exe -m atlas.desktop_gateway
```
Порт по умолчанию 8443, host 127.0.0.1. Gateway не включён автоматически в Compose без сертификатов. Для gateway в Docker нужен отдельный процесс/сервис с тем же ATLAS_DATABASE_URL, read-only mount сертификатов и HTTPS портом; CA private key в серверном runtime не нужен. Нельзя подключать SQLite gateway к PostgreSQL интерфейсу — профили отдельные.

Companion config (реальные пути заменяет владелец, хранить вне Git; пример не содержит ключей):
```json
{
  "server":"https://127.0.0.1:8443",
  "ca":"C:/private/atlas/ca.pem",
  "cert":"C:/private/atlas/device.pem",
  "key":"C:/private/atlas/device.key",
  "enabled":true,
  "expires_at":"2030-01-01T12:00:00+03:00",
  "roots":{"docs":"C:/Users/owner/AtlasDocuments"},
  "operations":["read_text","list","create_text"]
}
```
Из backend: `..\.venv\Scripts\python.exe -m atlas.companion C:/private/atlas/companion.json`. Companion не требует пароля владельца и session secret сервера. На другой машине с Python 3.12+ установите пакет командой `python -m pip install ./backend`, затем `atlas-companion C:/private/atlas/companion.json`. Windows MSI, служба и автообновление пока отсутствуют.
В вебе зарегистрируйте fingerprint, разрешите alias docs/нужные операции до выбранной даты. Для чтения включите desktop.read, для создания — отдельно desktop.write в Инструментах. Создайте запрос в Устройствах и проверьте/подтвердите его параметры в Подтверждениях. Состояние WAITING_DEVICE сохраняется до доставки; результат виден в Активности → Шаги и результаты, разговоре и журнале устройства. Очередь работает и для offline устройства до срока команды (не более часа/срока device grant). Если результат создания UNKNOWN, задача ставится на паузу без повтора; владелец проверяет указанный path вручную и только затем создаёт новый запрос.

## Защита каталога и восстановление
Traversal, absolute/UNC/drive paths, Windows alternate data streams, dot files, credential key extensions и trailing dot/space запрещены. POSIX использует anchored directory descriptors и O_NOFOLLOW для каждого компонента. Windows открывает и удерживает handles всех ancestors без share-write/delete, запрещает reparse points; это блокирует junction/symlink и замену родителя во время чтения. Hard-linked regular files, oversized/binary и известные шаблоны секретов блокируются. Директории OneDrive/reparse points могут оказаться недоступными — это безопасный отказ.
PREPARED/audit и command записаны до запроса. После claim lease 30 секунд; Companion просит permit и проверяет местный доступ. Result подтверждается только исходным certificate fingerprint, command ID и lease token. Text hash проверяется; это integrity результата доверенного Companion, не независимое чтение диска сервером. Повтор ACK не исполняет чтение второй раз. Если lease потеряна, UNKNOWN/PAUSED: автоматического повтора нет, владелец отменяет задачу и создаёт новый запрос. Отзыв/expiry/cancel блокируют pending и result. После последней проверки grant возможна короткая гонка с отзывом: уже прочитанные локально данные не отзываются, но сервер отказывается принимать результат после revoke. Доступ/ownership к самому local config — доверенная граница.

## Проверки и ограничения
pytest выполняет настоящее mTLS соединение локального gateway/client, чтение реального файла, полный путь через worker/approval, отказ без certificate и с неправильным назначением cert, revoke/expiry, queue dedup, UNKNOWN/cancel, traversal, junction/symlink/hardlink/limits/secrets. Windows и Linux filesystem branches проверяются на соответствующей платформе.
Нет Windows MSI, изменения существующих/удаления файлов, GUI automation, произвольных команд, production gateway hardening/нагрузочного теста, OCSP/CRL или удалённой независимой проверки содержимого диска. Device fingerprint revoke на сервере действует сразу для новых разрешений; dev CA рассчитана только на локальную проверку.

Основы транспорта и файловой защиты: [Python ssl](https://docs.python.org/3/library/ssl.html), [Python os](https://docs.python.org/3/library/os.html).

## Нативное окно Atlas, трей и голосовой компаньон Windows

Голосовой компаньон запускается при входе текущего пользователя Windows. По умолчанию действует строгая активация: каждая новая фраза должна начинаться с точного слова «Атлас», например «Атлас, расскажи о погоде». Отдельное «Атлас» не открывает микрофон для следующей произвольной фразы; после ответа обычная речь игнорируется. Это относится и к старым конфигам с ненулевым `follow_up_seconds`. Vosk распознаёт речь на компьютере; микрофонный звук не отправляется наружу. Иконка в трее позволяет открыть Atlas, открыть настройки голоса, приостановить микрофон, отключить автозапуск или завершить процесс.

В настройках **Активация** есть три режима: строгий (`wake_word`); разговор (`wake_word_followup`) с явно включённым окном 0–20 секунд; удержание клавиши (`push_to_talk`). Только разговор допускает похожие варианты обращения и речь без обращения в окне после ответа либо отдельного «Атлас». Внутри такого окна фоновая речь тоже может быть принята за запрос — не включайте его, если это нежелательно. Слова активации можно менять. В строгом режиме они должны стоять в начале фразы. PTT принимает речь только при удержании выбранной клавиши, без требования слова активации.

Кнопка **Выбрать модель ИИ в Atlas** открывает общие настройки моделей в окне Atlas (для старого уже открытого процесса — в браузере). После входа владельца измените **Основной помощник** и сохраните модели: следующий голосовой chat-запрос использует этот же профиль. Каталог RouterAI и ручной ID поддерживаются; модель для сложных задач и embeddings настраиваются отдельно. Whisper — локальное распознавание, Piper — голос; их выбор не меняет отвечающую LLM. API-ключи не передаются локальному окну или голосовому устройству.

Пункт **Настройки голоса** открывает локальное окно WebView2, а не удалённую страницу Atlas. В нём можно изменить профили, активацию, микрофон, частоту, push-to-talk, порог уверенности, окно продолжения, срок подтверждения, установленную Whisper-модель и CPU/CUDA-режим, Piper-озвучку и карточку. Настройки сохраняются атомарно в `%LOCALAPPDATA%\Atlas\Voice\voice.json`. Сертификаты, ключи и allowlist приложений из окна не редактируются; список моделей показывает только полные локальные каталоги. Безопасные сценарии редактируются как JSON; `enabled: false` отключает сценарий. Изменения параметров применяются автоматически, а для смены микрофона, его частоты или Vosk-модели используйте **Сохранить и перезапустить голос**. Обновление Python-кода требует выхода из трея и нового запуска процесса. Исторические VAD-параметры сохраняются ради совместимости; конец фразы определяет Vosk.

Открытие сайта, приложения или содержащего их сценария требует локального подтверждения, если включена соответствующая настройка. Скажите «подтверждаю» или «да» в течение 12 секунд; действие выполняется один раз. «Отмена»/«не надо» отменяет ожидающее действие. Ожидание подтверждения не открывает доступ произвольной речи: в строгом режиме новый запрос обязан начинаться с «Атлас», только такой запрос заменяет ожидающий. Истечение срока, пауза, диагностика микрофона или изменение настроек аннулируют подтверждение. «Закончи разговор» закрывает окно продолжения. Эти фразы относятся к локальному диалогу: они не отменяют серверную задачу и не разрешают server approvals. Похожие allowlist-названия и разные команды в альтернативных Vosk-гипотезах требуют повторения с точным названием.

Для оценки качества откройте **Сравнение распознавания**: выберите микрофон и модель, при желании введите контрольную фразу, нажмите **Подготовить сравнение**, дождитесь готовности, затем **Начать запись**. После трёхсекундного отсчёта записываются 12 секунд. Оба движка получают одну запись; выводятся тексты, задержки, RMS и WER (число замен/пропусков/лишних слов относительно контрольной фразы). Проведите несколько проб с командами, длинными запросами и фоновым шумом. На время записи обычный слушатель подтверждает паузу; если он занят ответом и не может остановиться за 8 секунд, проба завершается ошибкой. Отмена во время отсчёта не открывает микрофон; во время записи останавливает захват. Аудио и результаты сравнения не записываются на диск и не отправляются в Atlas. Распознанные шаблоны секретов скрываются. Тестовое окно выполняет только диагностику.

Whisper подготавливается в фоне при запуске слушателя. При сбое используется транскрипт Vosk; неуверенные Whisper-сегменты не заменяют его частично. Аудио 8/32 кГц преобразуется в 16 кГц через локальный [PyAV AudioResampler](https://pyav.basswood.io/docs/stable/api/audio.html#av.audio.resampler.AudioResampler). Выбранная неполная модель помечается недоступной, вместо молчаливой подмены другой моделью.

Для NVIDIA на Windows установите опциональный lock: `uv pip install --python .voice-venv/Scripts/python.exe -r backend/requirements-voice-gpu.lock`. Он сохраняет CPU voice-зависимости и добавляет официальные NVIDIA cuBLAS/cuDNN/NVRTC. Atlas подключает их DLL из своего окружения только внутри процесса. `cuda + float16` или `int8_float16` выбираются в настройках; `auto` при отсутствии CUDA DLL переходит на CPU. Требования движка: [faster-whisper GPU](https://github.com/SYSTRAN/faster-whisper#gpu); пакеты: [cuBLAS](https://pypi.org/project/nvidia-cublas-cu12/), [cuDNN](https://pypi.org/project/nvidia-cudnn-cu12/). Загрузка модели на GPU и проба тишиной не проверяют весь ASR: нужен хотя бы технический прогон речи.

Если Atlas не реагирует, откройте **Atlas — Настройки голоса** через «Пуск» и дождитесь зелёной надписи **Настройки подключены — можно выбрать микрофон**. В раскрывающемся списке **Микрофон** выберите нужное устройство; строка под списком покажет выбор. Сначала нажмите **Проверить микрофон**, затем **Проверить распознавание (6 секунд)** и скажите «Атлас, сделай погромче». Если текст появился, нажмите **Сохранить и перезапустить голос**, затем повторите команду в обычном режиме и проверьте раздел **Последние локальные команды**. Если уровень равен нулю или текст не соответствует вашей речи, выберите другой микрофон либо проверьте разрешение Windows на доступ классических приложений к микрофону. Если надпись о подключении не появляется, функции окна не загружены — повторное нажатие «Сохранить» не поможет; требуется диагностика запуска GUI. Для push-to-talk удерживайте выбранную клавишу во время произнесения фразы; в режиме слова активации клавиша не нужна.

Для установки без команд откройте двойным щелчком файл **`ops/desktop/Установить Atlas Voice.cmd`** в Проводнике. Он запускает установку в отдельное `.voice-venv`, загружает небольшую русскую модель и создаёт ярлыки.

Вариант для разработчика через PowerShell:

```powershell
./ops/desktop/install-voice.ps1
```

Для удаления автозапуска и ярлыков используйте `./ops/desktop/uninstall-voice.ps1 -Confirm`. Локальные модели и настройки удаляются только отдельным явным флагом `-RemoveLocalModels -Confirm`.

Установщик добавляет **Atlas Desktop**, **Atlas — Настройки голоса** и **Atlas Voice — слушает микрофон** в меню «Пуск», а также создаёт такие же ярлыки на рабочем столе. Поэтому для запуска, настройки или включения голосового слушателя больше не нужно открывать PowerShell: достаточно дважды щёлкнуть нужный ярлык. Окно также открывается из меню значка Atlas в трее. Это нативное окно Windows на WebView2 с полным текущим интерфейсом `https://atlas.prism-news.xyz`, включая серверные настройки. Профиль WebView2 отдельный от Chrome; при первом запуске войдите в Atlas обычным способом, сессия будет храниться в `%LOCALAPPDATA%\Atlas\Desktop\WebView2`. Локальный JS-bridge не подключён. Основной интерфейс требует интернет; локальные голосовые команды работают без сервера.

Установщик обновляет voice-окружение и добавляет фоновый голосовой процесс в автозапуск. Ручной запуск фонового режима:

```powershell
./.voice-venv/Scripts/pythonw.exe -m atlas.local_voice --tray
```

Конфигурация находится в `%LOCALAPPDATA%\Atlas\Voice\voice.json`; копия без персональных путей — `ops/desktop/voice.example.json`. Можно добавлять HTTPS-сайты, приложения по точному пути к `.exe`, варианты фраз и пользовательские последовательности безопасных действий. Произвольный код/команды конфигурацией не исполняются.

Локальные команды понимают распространённые варианты формулировок:

- Громкость: «сделай погромче», «прибавь звук», «погромче на 20», «потише на пять», «установи громкость на 35 процентов».
- Звук: «выключи звук», «заглуши звук», «верни звук», «сними беззвучный режим».
- Мультимедиа: «пауза», «приостанови видео», «продолжи музыку», «следующий трек», «дальше», «предыдущая песня», «назад».
- Сайты и приложения из локального списка: «открой…», «покажи…», «перейди на…», «зайди в…», «можешь открыть приложение…». Дополнительные фразы задаются в `site_phrases`, `applications.*.phrases` или списке `phrases` сценария.
- Справка и локальная информация: «что ты умеешь», «который сейчас час», «какая сегодня дата», «открой настройки голоса».

Для активации по умолчанию скажите «Атлас» и команду в одной фразе. Отдельное обращение и дальнейшая команда без «Атлас» доступны только в явно выбранном режиме разговора с ненулевым окном. Для громкости можно назвать изменение от 1 до 30 пунктов; без числа шаг составляет 10. Фразы сопоставляются с явными шаблонами и allowlist. Для типичных искажений Vosk разрешено только осторожное нечёткое сопоставление локальных команд и заранее разрешённых целей; свободный текст Atlas не переписывается.

Для свободной русской речи доступен второй локальный этап `faster-whisper`. Он запускается только после того, как Vosk не нашёл локальную команду, работает с тем же коротким буфером в памяти и не сохраняет аудио. Зависимость входит в `backend/requirements-voice.lock`; локальную модель нужно разместить, например, в `%LOCALAPPDATA%\Atlas\Voice\Models\whisper-small-ru`, указать этот абсолютный путь в `free_speech_model_path` и оставить `free_speech_enabled: true`. Atlas не скачивает модель сам и не принимает путь из ответа модели. До появления каталога модели безопасно используется Vosk-транскрипция.

Локальная речь ответа использует neural Piper TTS с русской мужской моделью `ru_RU-dmitri-medium`; модель загружается один раз, озвучка локальная, без SAPI и внешнего сервиса. Сеть и очередь озвучки работают в фоне. Esc или выбранная клавиша PTT (по умолчанию F8) останавливают текущие озвучку и ожидание; серверная задача не отменяется. В настройках можно включить **Слушать «Атлас, стоп» во время ответа** (`voice_interrupt_enabled: true`). Эхоподавления нет: рекомендуется использовать наушники; собственная речь из колонок может вызвать ложную остановку. Другие команды, новые запросы и подтверждения во время ответа игнорируются. После остановки обращайтесь заново со словом «Атлас». Без этой настройки микрофонные блоки во время собственной речи отбрасываются; пауза, выключение и диагностика останавливают захват микрофона.

На распознанную команду появляется компактная карточка обработки/результата. Она не сохраняет аудио и не принимает фокус клавиатуры. В системном трее цвет и заголовок показывают состояния «слушает», «обрабатывает», «отвечает», «пауза» и «ошибка». При первом старте Windows может запросить разрешение на микрофон. Автозапуск выключается из меню иконки в трее; повторный запуск установщика снова включает его.

## Голосовая связь с Atlas

Локальный Companion может передавать распознанную фразу в тот же разговор Atlas по своему исходящему mTLS-соединению. Пароль Atlas и cookie в Windows-конфигурацию не помещаются. Голосовой приём выключен до отдельного разрешения владельца:

1. В Atlas откройте **Устройства**, разрешите Companion и в его карточке включите **Голосовой Atlas на этом компьютере**. Выберите существующий разговор либо создайте отдельный голосовой диалог.
2. Обновите локальные голосовые зависимости `./ops/desktop/install-voice.ps1`. Скрипт дополняет пользовательский `voice.json`, сохраняя выбранные владельцем команды и сценарии.
3. Установщик добавляет фоновый запуск через `pythonw` и трей, ярлык **Atlas** в меню «Пуск» открывает полное окно Atlas. После активации словом «Атлас» локально известные команды выполняются на компьютере. Остальные фразы передаются в выбранный разговор.
4. Скажите «Атлас, режим задач», чтобы следующие фразы становились агентными задачами Atlas. Планировщик применяет текущие разрешения, журнал и подтверждения Atlas. «Атлас, режим разговора» возвращает обычный диалог. После перезапуска процесс начинает в режиме разговора.

Текст распознанной речи и ответа сохраняется в Atlas как обычная история/задача. Аудиозапись не передаётся и не сохраняется. `voice_enabled` хранится отдельно от файловых прав устройства; отзыв или истечение разрешения устройства блокирует голосовой канал. Серверная миграция `0013` добавляет эту настройку, перед production-развёртыванием её нужно применить через Alembic.

Gateway передаёт через `/voice-events/<task_id>` статусы, heartbeat, проверенные текстовые фрагменты и финальный ответ. Для chat-запроса к реальному совместимому провайдеру worker использует SSE; фрагменты появляются до завершения и попадают в очередь Piper. Незавершённое слово и защитный хвост удерживаются для проверки секретов; это не сырая выдача каждого токена. В demo нет LLM, у agent передаются статусы и готовый результат. Старый `/voice-result/<task_id>` остаётся fallback: после обрыва клиент не отправляет запрос повторно и не произносит уже переданный в очередь префикс второй раз. Если worker начал новую попытку или доступ отозван, текущая озвучка прекращается; результат проверяйте в Atlas. Полный ответ хранится в общей истории, голосовая озвучка ограничена 3500 символами.

Для нового серверного пути нужны миграция **`0014` через Alembic** и обновление worker/gateway; запуск старого сервера оставляет только финальные ответы. Новая таблица не меняет существующие задачи/сообщения. Временные фрагменты удаляются worker спустя 24 часа; при ошибке генерации очищаются сразу. После обновления локального Python-кода закройте Atlas Voice через меню трея и запустите заново: простой перезапуск слушателя внутри старого процесса не перезагружает модули. Локальные TCP/SSE и mTLS проверены с тестовым провайдером; текущая production-проверка описана ниже. Речь владельца и акустические условия требуют отдельной приёмки. Это не Realtime/WebRTC-звонок.

На время ответа включённое голосовое перебивание использует отдельный Vosk-словарь: обращение и только «стоп», «остановись», «останови ответ», «хватит», «замолчи», плюс неизвестная речь. Если выбранная Vosk-модель не поддерживает такой словарь, остаются Esc/PTT. Основной словарь команд и Whisper при перебивании не вызываются.
