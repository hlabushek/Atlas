# Голос Atlas — 3 октября 2026

Голосовой chat теперь генерируется отдельно от обычного веб-стиля: по умолчанию 2–4 коротких предложения, до 60 слов, естественная речь без Markdown; подробности по явной просьбе. Это инструкция модели, а не обрезка прочитанного текста и не дополнительный запрос для суммаризации. Потоковая очистка перед TTS убирает разметку, URL и блоки кода; исходный ответ в интерфейсе не переписывается очисткой. Реальная проверка DeepSeek дала 52 слова без разметки. Модель может нарушить инструкцию, поэтому это не жёсткая гарантия длины. После этого изменения — 273 pytest, 5 Vitest, 15 E2E и сборка PASS.

Основной экран: https://atlas.prism-news.xyz/#voice, с входом владельца. Локальное окно после подключения центра оставляет аппаратные настройки, установленные ASR/TTS-модели и явные пробы. Отвечающая LLM выбирается в общих настройках моделей, это не ASR. Сохранены строгая активация перед каждой фразой, Whisper medium/CUDA float16, Piper и серверная DeepSeek V4.1 Flash.

## Семь приоритетов

1. mTLS SSE до слушателя и cookie-authenticated SSE до веба: статус, проверенные фрагменты, шаги и события инструментов, ожидание approvals и итог. TTS смысловыми фрагментами вне цикла микрофона. Esc/PTT останавливают речь/ожидание, не серверную задачу. Отдельная отмена использует общий веб-сервис и разрешена только для собственных голосовых задач устройства. Кнопка привязана к показанному task_id; выполненные эффекты не откатываются. Голосовое перебивание — явная настройка, по умолчанию выключена, AEC отсутствует. Для старого gateway сохранён fallback чтения результата без повторной отправки. SSE убирает клиентский HTTP polling, но внутри сервера ещё есть короткие проверки БД, это не полный pub/sub.
2. Общий Vosk проверяет обращение/уверенность; ограниченная командная грамматика — дополнительная гипотеза и контроль конфликтов, не источник придуманного обращения. Свободная речь уточняется локальным faster-whisper после activation gate. Результат: intent/target/confidence/risk/needs_confirmation. Конфликтующие сценарии/цели запрашивают выбор, не выбирают первое совпадение. Confidence не является откалиброванной вероятностью правильного понимания.
3. Общая capability-модель локальных действий и серверных инструментов: grants, риск, подтверждение, отменяемость, обратимость, аудит, TTL. Метаданные не выдают права. Локальные grants проверяются перед каждым шагом, срок разрешений задаётся владельцем. Высокорисковые серверные действия всегда требуют approval; старые gates сохраняются. Shell-инструментов для модели нет. Для сайта проверяется принятие браузером запроса, не загрузка страницы.
4. «Голос»: микрофон/уровень, режим/состояния, фраза/маршрут, шаги задачи, остановка/отмена/повтор/отказ, mute, история без аудио, приватность, сценарии и dry run. Ревизия настроек защищает от перезаписи другой сессией. Controls одноразовые, с TTL; неподтверждённый UNKNOWN не повторяется. Неверный сценарий не применяется и не блокирует mute/отзыв grants/управление; ошибка видна в центре. Цели сначала разрешаются локальным allowlist.
5. Видимая сессия до пяти реплик, срок 0–120 секунд, без новых полномочий. «Ещё на пять» продолжает относительное изменение громкости. «Это не то» снимает ожидание либо возвращает громкость/mute по обратимому снимку. Чужие окна, сайты и серверные операции не откатываются автоматически. Короткий контекст передаётся следующей LLM-реплике; права памяти Atlas не расширены. Настоящий дневник требует настроенной интеграции, данных и approvals, контекст не заменяет их.
6. Лаборатория: явная проба в памяти, сравнение Vosk/Whisper, серия подтверждённых проб, WER/CER, правильность intent + цели/параметров, пропуски, ложные обращения на отрицательных пробах, p50/p95, CPU/RAM и доступная GPU-телеметрия. Условия: тишина, музыка, наушники, расстояние, быстрые команды, имена. Результаты группируются по модели, одна проба учитывается один раз. Отдельная кнопка реального Piper-прогона и runtime-метрики; пустые выборки — «не измерено», не ноль.
7. Local-only и локальное ASR + серверный Atlas, отключение хранения текста, фильтр чувствительных TTS-ответов, полный программный mute. Local-only не отправляет фразы; метаданные/защищённое управление остаются. Mute останавливает захват, но оставляет канал включения. Аудио по умолчанию не сохраняется/не отправляется. Секретоподобные строки и известные секреты запрещены независимо от настроек; фильтр не универсальная DLP.

## Хранение и его границы

Без сохранения разговор не создаёт постоянных сообщений. Текст временно нужен очереди; после подтверждения доставки очищаются задача/ответ, контекст и фрагменты, при потере клиента завершённый запрос очищается после 15 минут. Незавершённый сначала должен закончиться. Метаданные, digest для idempotency и обязательный аудит остаются. Agent-задачи с инструментами требуют журнала и отклоняются при выключенном сохранении. Это не режим «ни одного байта на диск».

Выключение хранения/local-only очищает текст текущего состояния и voice-событий устройства, не старые обычные диалоги, сторонние журналы провайдера или зашифрованные резервные копии. Локальная история скрывает прежний command-текст; старый файл удаляется штатной кнопкой очистки. Voice-события хранятся до суток, числовые замеры — последние 256.

## Открытая живая приёмка

Цели локальная команда p95 ≤ 1 с, начало ответа ≤ 1–1,5 с, перебивание ≤ 300 мс **не подтверждены** на речи владельца. Обработка записи не равна задержке после живой фразы. Runtime конец фразы оценивается по уровню микрофона, первый звук TTS — передача в sounddevice, не акустический замер. Доля false wake на отрицательных пробах не равна событиям в час. Маленькая выборка не подтверждает p95.

Piper остаётся установленным реальным TTS. Silero/whisper.cpp не интегрированы и не объявляются выбранными. Для выбора движков нужны пробы владельца и прослушивание альтернатив; фоновой записи и платных LLM-проб в этом кластере нет. Приоритет 6 закрыт в части инструментария, экспериментальная приёмка открыта.

Проба: «Голос» → «Микрофон и локальные модели» → условие/ожидаемая команда → подготовить → явно начать → проверить результат → «Учесть завершённую пробу». Отрицательные фоновые пробы также явные. Аудио остаётся в памяти; в центре доступны числовые метрики.

## Эксплуатация и проверки

Additive Alembic 0015: на восстановленной production-копии 0014→0015 все 37 прежних таблиц совпали по SHA-256/количеству. Production сохранила количества строк всех прежних таблиц. Encrypted restore 0015 в отдельную временную БД прошёл: 42 таблицы. PostgreSQL/Redis и чужие проекты не останавливались; прежние образы/исходники сохранены, автоматического downgrade/перезаписи БД нет.

Тесты проверяют отзыв grants, секреты, TTL, одноразовость, хранение, scoped cancel, миграцию и настоящий mTLS/SSE. E2E центра использует тестовые события и controls; live-интеграция отдельно проверяется read-only: реальный слушатель/микрофон, оба SSE-канала, owner auth и сохранённая модель без аудио/LLM. Запуск из корня: `.voice-venv\Scripts\python.exe scripts/check_voice_center.py`.

Итог: 256 pytest, 5 Vitest, 15 E2E, сборка frontend, Ruff и scoped mypy восьми модулей прошли. Frontend lint — без ошибок, семь прежних предупреждений в других файлах. Windows IPC тестов использует отдельные имена и не приостанавливает настоящий слушатель. Опция smoke `--mute-test` делает явные mute/unmute и проверяет подтверждённый результат, возвращая исходное включённое состояние; живой прогон прошёл. Первый результат SSE иногда задерживался внешним HTTPS-прокси: для точного `/api/voice/events` отключены buffering/cache/gzip на обоих Nginx, проверены конфигурации и повторная живая доставка. Семантика buffering: [официальная документация Nginx](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffering).
