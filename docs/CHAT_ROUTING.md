# Быстрые и вдумчивые ответы

По просьбе владельца 3 октября 2026 на сервере:

- основная модель: RouterAI `deepseek/deepseek-v4-flash`;
- модель сложных задач и планирования: RouterAI `deepseek/deepseek-v4.1-flash`;
- включено `auto_chat_routing`; память/embeddings, бюджеты, ключи и Whisper/Piper не изменены.

В веб-чате «Авто» использует общие правила `chat_routing.py`. «Быстрый ответ» и «Вдумчивый ответ» принудительно выбирают роль. В голосовом разговоре и подключённом Telegram применяются те же правила. В режиме задач план всегда составляет planner; это не предоставляет новые инструменты или права.

Обычный запрос идёт основной модели. «Подумай», «обдумай», «проанализируй», «обоснуй», «докажи», «сравни», «разбери подробно/детально», «объясни подробно/детально», «реши задачу/уравнение», «проверь код/расчёт», «составь план» выбирают planner. Запрос длиннее 1200 символов тоже выбирает planner. Начальное «быстро», «кратко», «коротко» или «ответь кратко» выбирает быстрый путь раньше правила сложности. Это явные эвристики, а не глубокая классификация смысла; иначе сформулированный сложный запрос может остаться быстрым. Классификатор LLM не вызывается, платных дополнительных запросов нет.

Флаг автоматизации можно выключить в «Настройки → Модели Atlas»: тогда «Авто»/голос используют main, ручной planner продолжает работать. Настройки прежних установок без нового флага по умолчанию не включают автоматизацию и не меняют выбранные модели.

При включённой схеме быстрый ответ ограничен меньшим из общего лимита и 512 токенов. Для точного V4 Flash на RouterAI отправляется `reasoning.enabled=false`; другие модели/провайдеры не получают этот параметр. Вдумчивый ответ сохраняет общий предел (сейчас 1024) и получает инструкцию проверять допущения, не раскрывая внутренние рассуждения. Голос в обоих случаях сохраняет краткость 2–4 предложения по умолчанию; подробности — по явной просьбе, очистка Markdown перед TTS остаётся.

Выбранная роль, модель, причина маршрутизации и ревизия фиксируются в `Task.model_profile` до начала генерации. Повтор с прежним request_key возвращает тот же профиль даже после изменений настроек. Ручная смена режима с тем же ключом — конфликт 409. Сбой не вызывает второй платный запрос к другой модели. Уже созданные задачи остаются на прежних профилях.

Тарифы в бюджетном ledger на этой установке остаются неизвестными (0), денежные лимиты не были настроены и не менялись. Не следует считать отображаемый расход в токенах точной суммой в рублях. Цены RouterAI зависят от фактического провайдера, его доступности, времени суток и курса; самые дешёвые позиции могут использовать quantization. Без проверенных тарифов включённый денежный лимит блокирует запрос, а не пропускает его бесплатно. Для выбора моделей использован официальный каталог RouterAI:

- https://routerai.ru/models/deepseek/deepseek-v4-flash
- https://routerai.ru/models/deepseek/deepseek-v4.1-flash

Проверки двух реальных проб через mTLS/SSE, без аудио, TTS и постоянного текста: V4 — первый текстовый фрагмент 2,30 с, весь ответ 2,69 с / 29 слов; V4.1 — 34,39 с и 34,64 с / 47 слов. Обе задачи COMPLETED, ровно по одному provider-вызову, usage KNOWN. Это два разных вопроса и единичные измерения, не честный сравнительный бенчмарк и не p95. Время не включает ASR и синтез речи. Скрипт `scripts/check_voice_routing.py --live` делает две платные пробы; не запускать фоном или автоматически.

Развёртывание: `ops/voice-rollout/dual-models.sh`, ревизия настройки 24 → 25 с CAS и Audit, без миграции схемы 0015. Предыдущие образы `pre-dual-models-20261003`, исходники и прежняя конфигурация сохранены в `/opt/atlas/staging/dual-models-20261003`; перед изменением проверен свежий зашифрованный backup. Секретов в архивах кода и конфигурации моделей нет. Для отката нужны прежние образы/исходники и отдельное восстановление только ModelPreferences с новой ревизией/аудитом; нельзя бездумно восстанавливать всю БД поверх последующей работы владельца.
