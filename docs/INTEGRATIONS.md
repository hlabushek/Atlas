# Интеграции этапов 3/4
## Telegram
В .env сервера задайте ATLAS_TELEGRAM_BOT_TOKEN и числовой ATLAS_TELEGRAM_OWNER_ID. Токен создаёт владелец у BotFather; не вводите его в Atlas. Для SOCKS5 задайте ATLAS_TELEGRAM_PROXY как URL вида `socks5://user:password@host:port`; HTTPX использует SOCKS-транспорт из зафиксированной зависимости socksio. Перезапустите API/scheduler/telegram: `docker compose up -d`. В веб-разделе Telegram получите одноразовый код, отправьте боту `/start CODE`. Код хранится только как SHA-256 hash, TTL 10 минут. Принимаются только private сообщения заданного owner ID. Другие аккаунты не могут привязаться, читать историю или подтвердить действие.
Polling сохраняет update offset и dedup keys. Тексты идут в общую DB очередь worker. Веб открывает тот же conversation_id. Инициативы имеют собственные разговоры; отправка переключает текущий Telegram разговор, явный reply_to_message возвращает исходный контекст. Approvals привязаны к существующей записи и текущему владельцу, проходят тот же policy gate, повтор решения безопасен.
Outbox пишет intent до sendMessage. После timeout/crash доставка UNKNOWN не повторяется автоматически: Telegram Bot API не предоставляет клиентский idempotency key для sendMessage. Статус виден в Инициативах; автоматического reconciliation нет. Quiet hours/expiry/opt-in/recipient/daily limit проверяются перед отправкой инициатив. Обычные ответы и approvals не подавляются quiet hours.
Живой бот в этой рабочей среде не проверен; тесты используют подменённый transport. Принимаются TXT/MD/CSV/JSON до 64 КиБ и голос до 2 минут/5 МиБ. Для голоса используется RouterAI Universal-3.5 Pro; отдельный бюджет хранит RUB в копейках и ограничивает дневной/месячный расход. Текущий тариф сервера по умолчанию — 41 коп./мин (`ATLAS_TELEGRAM_STT_KOPECKS_PER_MINUTE`); проверьте его перед включением STT. Нужен `ATLAS_ROUTERAI_API_KEY`. Платные запросы и живой бот тестами не вызывались. Редактирование кнопок после решения и answerCallbackQuery пока отсутствуют.

## Проактивность
Запускается отдельно `python -m atlas.scheduler`; в Compose сервис scheduler. По умолчанию выключена. Источники: явное напоминание, успешно завершённая агентная задача после opt-in, новое/изменённое задание и учебный дедлайн в ближайшие 24 часа. Это правила, не решения LLM. Единая event identity, IANA timezone, дневной limit, cooldown, max repeats, expires_at и reply_id хранятся в БД. Ответ в другом веб-клиенте или Telegram прекращает повтор; молчание не считается прочтением. При неоднозначности связь не угадывается.

## Навыки и MCP
Манифест содержит id, version, description, kind, compatibility=atlas-v1, endpoint, credential_env, instructions, read_tools. Произвольные дополнительные поля, shell/код и неподдерживаемые builtin запрещены. Установка явная; затем отдельное включение и выдача grants. Отключение/удаление отзывает grants и сохраняет результаты/учебные данные. Instructions загружаются отдельным owner endpoint по выбранному навыку, не добавляются автоматически в каждый запрос модели.
В ATLAS_INTEGRATION_HOSTS укажите доверенные hostname через запятую. HTTP разрешён только для явно разрешённого хоста, предназначен для локальных тестовых сервисов; удалённые сервисы подключайте по HTTPS. Redirects запрещены. Credential reference — только переменная вида ATLAS_CONNECTOR_NAME; значение становится Bearer header, не хранится в manifest/model/memory. Endpoint не содержит credentials, query или fragment. Выбор хоста доверяет всем его портам; это allowlist владельца, не защита от злонамеренного доверенного сервера.
Пример manifest:
```json
{"id":"my-mcp","version":"1.0.0","description":"Выбранный источник","kind":"mcp","endpoint":"https://trusted.example/mcp","read_tools":["search"],"credential_env":"ATLAS_CONNECTOR_SERVICE"}
```
MCP SDK действительно делает initialize/tools/list/tools/call по Streamable HTTP. Принимаются только выбранные инструменты с readOnlyHint=true и без destructiveHint=true. Схемы ограничены размером, без refs/regex; вход проверяется jsonschema. Каждый внешний вызов требует scoped approval; policy проверяется вновь перед execute. Ответ ограничен размером/timeout. Read-only annotation — декларация сервера: владелец должен доверять endpoint. Нет локального stdio, установки Python/JS кода или отдельной OS песочницы. Health/history доступны в UI.
REST manifest использует kind=rest и фиксированный endpoint; предоставляется инструмент skill-id.fetch с пустыми аргументами. Реальные HTTP MCP и REST проверены на локальных серверах в pytest, не на пользовательском аккаунте.

## Дневник
Дневник показывает сохранённые реальные задания school.mos.ru, если они импортированы, и отдельные учебные задачи. Расписание хранится по конкретным датам; день без записи явно обозначен как не загруженный. Владелец выбирает дату в интерфейсе или спрашивает в чате расписание на день/неделю и ДЗ на день/списком. Чат читает только сохранённые данные, указывает время синхронизации и не вызывает модель для таких запросов. API владельца `/api/diary/import/school-mos` принимает `homework` и/или `days` с датой и уроками; повторный импорт не создаёт дублей. Источник сохраняется у задания; уникальность provider/external_id, hash и revision определяют new/changed события. StudyTask обновляется без дубля; owner может отметить выполнение. Study plan — сортировка по дедлайнам и условные 30 минут, без оценки знаний/нагрузки моделью.

DemoDiaryProvider доступен отдельно как явно обозначенные тестовые данные. Установка diary-demo 1.0.0 → включение → grants → sync task → approval. Реальный импорт ДЗ ранее проверен, но импорт уроков с текущих страниц school.mos.ru ещё не проверен: сайт недоступен из-за технических работ. Запись расписания через API сама по себе не означает, что Atlas получил его с сайта.
RestDiaryProvider реально читает нормализованный JSON контракт: `homework` массив с external_id/subject/title/due_at с timezone/grade и `schedule` массив. Авторизация Bearer env. 401/403 сигнализируют повторную авторизацию. Неизвестный школьный API к этому контракту автоматически не подключается. Провайдер можно передать общему sync(session, provider, provider_id, source) в отдельном адаптере; UI выбора реального провайдера пока нет.

Optional PlaywrightDiaryProvider извлекает homework по явно заданным CSS selectors и storage_state, зашифрованному Fernet. Нужно установить backend/requirements-browser.txt и Chromium (`python -m playwright install chromium`) в окружении адаптера; стандартный Docker образ их не содержит. Адаптер ограничивает браузерные запросы hostname allowlist. Сайт/SSO/assets должны быть явно разрешены. Selectors: authorized, rows, subject, title, due (элемент с datetime), необязательные grade и id_attribute (по умолчанию data-id). Для расписания требуется отдельное отображение конкретного сайта.
Для первоначального входа владелец вручную запускает scripts/authorize_diary.py с ATLAS_DIARY_URL, ATLAS_DIARY_SESSION_KEY (Fernet key), ATLAS_DIARY_SESSION_PATH и ATLAS_INTEGRATION_HOSTS. Открывается браузер: владелец проходит login/MFA/CAPTCHA и нажимает Enter в терминале. Скрипт никогда не вызывается моделью или scheduler. State сохраняется зашифрованно; путь предпочтительно вне репозитория, Windows ACL ограничьте владельцем. Key — только env, encrypted file исключён .gitignore/.dockerignore. Истёкшая сессия требует того же ручного входа. На школьном сайте этот optional adapter не проверен, конкретные selectors/API неизвестны.

## Следующие интеграции
Универсальный Chrome адаптер находится в `integrations/school-mos-chrome` (локальная папка сохранена для установленной распакованной версии). Он использует `activeTab` для чтения текущей страницы, передаёт модели только краткую структуру DOM, а не значения полей; модель возвращает CSS-рецепт, владелец проверяет его до сохранения. Импорт данных ограничен выбранными текстовыми элементами и owner-only API `/api/connectors/{id}/import`.

Рецепт — данные, не код. Произвольный JavaScript, shell, клики и формы запрещены. Автообновление по конкретному HTTPS-домену выключено по умолчанию и требует явного включения и отдельного optional host permission Chrome; после разрешения синхронизируется только открытая страница при загрузке и раз в 15 минут. Отключение коннектора отзывает агентский grant и останавливает импорт. Агент получает данные только через scoped `connector.<id>.read` tool; grant закрыт по умолчанию и каждый вызов всё равно требует подтверждения. CAPTCHA/MFA/bot protection не обходятся. Подробности и ограничения — в README расширения.
